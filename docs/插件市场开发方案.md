# DSH Desktop 插件市场开发方案

> 本文档用于指导并记录 DSH Desktop 插件市场首版实现。
>
> 首版已按本文档落地 Tauri 前端、Rust 后端、契约测试和协议测试包；插件开发基础规则参见同目录的《plugin开发文档.md》，两者冲突时以 DSH 当前运行时及官方 Cordis 接口为准。

## 1. 目标与范围

插件市场属于 **DSH Desktop 的 Tauri 桌面外框**，不注入 DeepSeek Harness Web 页面，也不替换 DSH 自身的侧边栏、设置页或会话区域。

首版目标如下：

- 在窗口顶部左侧 Logo 旁增加“插件市场”按钮。
- 将桌面端扩展为“首页 / DSH 页面 / 插件市场”三种视图。
- 通过 DSH CLI 搜索、安装和卸载 `@p-dsh-market/*` 插件。
- 仅管理 `$DSH_HOME/profiles/web`，不跨 profile 同步。
- 插件安装或卸载后提示用户重启 DSH，不做热加载或自动重启。
- 市场插件采用单包组合形态，同时承载 Skill、宿主逻辑和 Web UI。

首版不包含以下能力：

- 插件更新或批量更新。
- 保留依赖的启用、停用。
- 动态 Cordis 插件的 `define/run/stop/undefine` 管理。
- 跨 `web`、`desktop` 或其他 profile 的安装同步。
- 第三方 scope、Git 地址、本地目录或任意 npm 包安装。

## 2. 总体架构

```text
┌──────────────────────────────────────────────────────────┐
│ DSH Desktop 标题栏                                      │
│ Logo | 插件市场                         窗口控制按钮     │
├──────────────────────────────────────────────────────────┤
│ home            │ dsh iframe            │ market         │
│ 桌面配置首页     │ DeepSeek Harness Web  │ 插件市场页面    │
└──────────────────────────────────────────────────────────┘
                            │ Tauri invoke
                            ▼
┌──────────────────────────────────────────────────────────┐
│ Rust 插件市场模块                                        │
│ 运行时选择 │ pnpm 准备 │ 参数校验 │ 单任务互斥 │ 输出整理 │
└──────────────────────────────────────────────────────────┘
                            │ argv，不经过 Shell
                            ▼
┌──────────────────────────────────────────────────────────┐
│ 当前桌面运行来源对应的 DSH CLI                           │
│ dsh plugin --profile web <pnpm arguments...>             │
└──────────────────────────────────────────────────────────┘
                            │
             ┌──────────────┴──────────────┐
             ▼                             ▼
      npm registry                  web profile
      搜索与包清单                  package.json/node_modules
```

职责边界：

| 层级 | 职责 |
| --- | --- |
| Tauri 前端 | 三视图导航、搜索输入、插件卡片、确认操作、状态与错误展示 |
| Rust 后端 | 选择 DSH CLI、准备私有 pnpm、执行命令、校验包名和清单、串行化写操作 |
| DSH CLI | 在 `web` profile 内转发 pnpm 命令，并 reconcile `dsh.profile.bundles` |
| 市场插件包 | 通过 `dsh.bundle.patch` 自动挂载，注册 Skill、宿主逻辑和 Web UI |

## 3. 桌面端页面设计

### 3.1 标题栏入口

- 在现有 `DSH Desktop` 品牌区域旁增加独立的“插件市场”按钮。
- 按钮始终可见，不依赖 DSH 是否已经启动。
- 按钮需要阻止 `mousedown` 冒泡，避免点击时触发窗口拖动。
- 当前位于市场页面时显示选中态，并提供正确的 `aria-label`、焦点样式和键盘操作。
- 原品牌按钮继续负责首页与已启动 DSH 页面之间的切换，不复用为市场入口。

### 3.2 三视图状态

现有 `viewMode` 扩展为：

```text
home | dsh | market
```

切换规则：

- `home`：展示桌面配置首页，隐藏 DSH iframe 和市场页面。
- `dsh`：仅在存在 `webUrl` 时展示 DSH iframe。
- `market`：展示市场页面，隐藏首页和 DSH iframe；不得销毁已加载的 iframe URL。
- DSH 尚未启动时进入市场，不应被 `updateView()` 强制切回首页。
- DSH 停止后，若当前处于 `dsh` 则回到首页；若处于 `market` 则继续停留市场。
- DSH 页面专属的“首页 / 更新 / 升级 / 关闭 DSH”操作栏在市场页面隐藏。

### 3.3 市场页面

市场页面复用首页的主题变量、卡片圆角、间距、阴影、按钮层级和响应式断点，包含：

1. **页面头部**
   - 标题“插件市场”。
   - 说明当前仅管理 `web` profile。
   - DSH 运行时与 pnpm 准备状态。

2. **搜索区**
   - 插件名称搜索框。
   - “搜索”按钮，支持 Enter 提交。
   - 空查询用于列出 `@p-dsh-market/*` 范围内的插件。
   - 搜索期间显示加载状态，阻止重复提交。

3. **结果区**
   - 每张卡片显示展示名、完整包名、最新版本、描述和能力标签。
   - 已安装时显示当前版本和“已安装”状态。
   - 未安装插件提供“安装”按钮；已安装插件提供“卸载”按钮。
   - 不满足市场协议的包不进入结果列表。
   - 空结果、网络失败、运行时缺失分别展示不同提示。

4. **操作反馈区**
   - 显示当前安装或卸载对象、执行状态和受控日志摘要。
   - 写操作成功且 DSH 正在运行时，显示“磁盘状态已更新，重启 DSH 后生效”。
   - DSH 未运行时，显示“将在下次启动 DSH 时生效”。

### 3.4 运行时缺失

插件市场入口保持可用，但页面进入只读状态：

- 说明尚未准备好可用的 DSH 运行时。
- 禁用搜索、安装和卸载按钮。
- 提供返回首页的操作，引导用户安装桌面托管运行时或选择本地运行时。
- 不因为进入市场而自动安装 DSH，也不隐式切换运行来源。

## 4. Tauri 接口与数据结构

### 4.1 Tauri 命令

Rust 后端提供以下三个命令：

```text
search_market_plugins(query) -> MarketSearchResult
install_market_plugin(name, version) -> MarketOperationResult
uninstall_market_plugin(name) -> MarketOperationResult
```

命令约束：

- 固定操作 `web` profile，前端不能传入 profile 名称。
- 前端不能传入 registry、命令参数、可执行文件路径或工作目录。
- 安装与卸载必须在 Rust 后端再次校验包名和远端清单，不能信任之前的搜索结果。
- 安装使用搜索时返回的确定版本 `name@version`，避免搜索与安装之间因 `latest` 漂移而安装不同版本。

### 4.2 MarketPlugin

```text
name               完整 npm 包名
displayName        dsh.market.displayName
version            registry 最新版本
description        npm 包描述
capabilities       dsh.market.capabilities
installed          是否已安装到 web profile
installedVersion   当前已安装版本；未安装时为空
```

### 4.3 MarketSearchResult

```text
query              规范化后的查询词
plugins            通过校验的 MarketPlugin 列表
runtimeReady       是否存在可调用的 DSH 运行时
packageManagerReady 私有 pnpm 是否可用
message            空结果、只读状态或降级说明
```

### 4.4 MarketOperationResult

```text
ok                 操作是否成功
operation          install | uninstall
name               目标包名
version            安装版本；卸载时可为空
message            面向用户的结果摘要
log                 截断并脱敏后的命令输出
restartRequired     操作完成时 DSH 是否正在运行
```

错误通过统一的 Tauri command error 返回，前端必须恢复按钮状态并保留页面已有搜索结果。

## 5. 搜索与安装协议

### 5.1 DSH CLI 命令

所有插件管理操作必须调用当前桌面运行来源对应的 DSH CLI：

```sh
dsh plugin --profile web search <关键词> --json --search-limit 50
dsh plugin --profile web view <包名> --json
dsh plugin --profile web list --depth 0 --json
dsh plugin --profile web add <包名>@<确定版本>
dsh plugin --profile web remove <包名>
```

`dsh plugin` 会把后续参数转发给 pnpm，并在命令结束后 reconcile `dsh.profile.bundles`。市场后端不得直接修改 profile 的 `package.json`、锁文件、`node_modules` 或 `cordis.patch.yml`。

### 5.2 搜索流程

1. 校验 DSH 运行时和桌面私有 pnpm。
2. 限制查询长度并去除首尾空白，不允许查询内容改变固定 profile 或命令结构。
3. 调用 `dsh plugin --profile web search ... --json`。
4. 解析 JSON，忽略非对象、缺失名称或字段类型错误的条目。
5. 仅保留满足以下正则语义的名称：

   ```text
   ^@p-dsh-market/[a-z0-9][a-z0-9._-]*$
   ```

6. 对候选包调用 `view` 获取发布清单并执行市场协议校验。
7. 调用 `list --depth 0 --json` 合并已安装状态。
8. 按包名去重后返回前端。

pnpm/npm 搜索是模糊搜索；`scope` 或关键词只负责缩小候选范围，不能替代后端的精确前缀和正则校验。

### 5.3 插件包清单协议

可安装的 `@p-dsh-market/*` 包必须在 `package.json` 中同时声明标准 DSH 字段和市场字段：

```json
{
  "name": "@p-dsh-market/example",
  "version": "0.1.0",
  "type": "module",
  "main": "lib/index.js",
  "exports": {
    ".": "./lib/index.js",
    "./client": "./lib/client.js",
    "./cordis.patch.yml": "./cordis.patch.yml",
    "./package.json": "./package.json"
  },
  "files": [
    "lib/index.js",
    "lib/client.js",
    "cordis.patch.yml"
  ],
  "publishConfig": {
    "access": "public"
  },
  "dsh": {
    "client": {
      "platform": "web"
    },
    "bundle": {
      "patch": "./cordis.patch.yml"
    },
    "market": {
      "displayName": "示例插件",
      "capabilities": ["skills", "host", "client"]
    }
  }
}
```

市场校验要求：

- `main` 为非空字符串。
- `exports["./client"]` 存在。
- `dsh.client.platform === "web"`。
- `dsh.bundle.patch` 为非空字符串。
- `dsh.market.displayName` 为非空字符串。
- `dsh.market.capabilities` 是字符串数组，并同时包含 `skills`、`host`、`client`。

该校验确认包的结构声明，不对 npm 包代码作安全背书，也不能静态证明插件运行时一定成功注册 Skill。实际加载错误仍由 DSH 启动日志暴露。

### 5.4 组合插件约定

一个市场包同时包含：

- **宿主半**：通过 Cordis `apply(ctx)` 注册 Skill、命令、服务或路由，所有副作用均纳入 `ctx.effect` 或返回 disposer。
- **浏览器半**：通过 `exports["./client"]` 和 `dsh.client.platform` 被 Web 前端加载，使用正式槽位注册 UI。
- **bundle patch**：插入该插件的 Cordis 配置行，使 `dsh plugin add` reconcile 后自动进入 `dsh.profile.bundles`。

`cordis.patch.yml` 最小示例：

```yaml
- insert:
    - id: p-dsh-market-example
      name: '@p-dsh-market/example'
      inject: [skills]
```

宿主半负责通过 `ctx.skills.register(...)` 或 `ctx.skills.registerProvider(...)` 注册 Skill；浏览器半不得通过硬编码 DOM 选择器修改 DSH 页面。

## 6. 桌面私有 pnpm

### 6.1 目标

DSH 的 `plugin` 命令依赖 pnpm，但 DSH Desktop 当前只保证内置 Node/npm。插件市场不能要求最终用户预先全局安装 pnpm，也不能修改用户的系统 PATH。

### 6.2 私有工具目录

固定使用桌面数据目录下的私有位置：

```text
%LOCALAPPDATA%\dsh-desktop\tools\
├── package.json
└── node_modules\
    ├── pnpm\
    └── .bin\pnpm.cmd
```

pnpm 版本应在桌面代码中固定，不跟随 registry 的 `latest` 自动漂移。升级 pnpm 需要随桌面版本显式调整并经过回归测试。

### 6.3 准备流程

1. 检查私有 `.bin/pnpm` 或 Windows 下的 `.bin/pnpm.cmd` 是否存在。
2. 执行 `pnpm --version`，确认版本与桌面固定版本一致。
3. 缺失或版本不匹配时，使用桌面内置 npm 安装固定版本到私有 tools 目录。
4. 安装采用参数数组、隐藏控制台窗口，并收集有限长度的 stdout/stderr。
5. 调用 DSH CLI 时，仅给该子进程的 `PATH` 前置私有 `.bin` 目录。
6. 不写入系统环境变量，不覆盖用户全局 pnpm。

准备 pnpm 需要访问 npm registry。失败时市场保持只读，展示网络、registry 或磁盘错误，不回退执行未经确认的系统全局工具。

## 7. 运行来源与命令执行

### 7.1 托管运行时

托管模式复用桌面私有 Node 和当前固定版本的 DSH `lib/bin.js`：

```text
<desktop-node> <managed-runtime>/node_modules/@deepseek-ai/dsh/lib/bin.js plugin --profile web ...
```

### 7.2 本地运行时

本地模式复用桌面已经检测并选择的本地运行方式，与启动 DSH 时保持一致：

```text
<local-command> --no-install @deepseek-ai/dsh plugin --profile web ...
```

市场不能因为执行插件命令而切换 `runtimeSource`，也不能静默改用另一个 DSH 版本。

### 7.3 子进程安全

- 一律通过可执行文件加 argv 数组启动，不使用 `cmd /c`、PowerShell 字符串或 Shell 拼接。
- 固定 `DSH_HOME` 为桌面正在使用的目录。
- 工作目录使用已解析的安全目录，不接受前端输入。
- 包名、版本号和查询长度均在 Rust 后端校验。
- 日志设置最大字节数，超出时保留尾部并标记截断。
- 不记录完整环境变量、Token、registry 凭据或 npm 认证文件内容。
- Windows 子进程继续使用隐藏窗口参数，避免弹出控制台。

## 8. 安装、卸载与重启语义

### 8.1 单任务互斥

- 搜索可以在没有写操作时执行。
- 任一安装或卸载开始后，其他写操作立即返回“已有插件操作进行中”。
- 前端同时禁用所有插件卡片上的写按钮。
- 互斥状态必须在成功、失败和异常退出后释放。

### 8.2 安装

1. 校验包名、版本及市场清单。
2. 若相同包已安装，拒绝重复安装，并返回当前版本。
3. 执行 `dsh plugin --profile web add name@version`。
4. 命令成功后重新读取已安装状态，只有目标包确实存在才返回成功。
5. DSH 正在运行时设置 `restartRequired: true`；未运行时为 `false`。

### 8.3 卸载

1. 校验包名属于 `@p-dsh-market/*`。
2. 确认目标当前已安装；未安装时拒绝卸载。
3. 执行 `dsh plugin --profile web remove name`。
4. 命令成功后重新读取状态，只有目标包确实消失才返回成功。
5. DSH 正在运行时设置 `restartRequired: true`；当前进程中的插件效果持续到用户重启 DSH。

### 8.4 待重启状态

- 前端在本次桌面会话内保存待重启标记和涉及的插件名称。
- 用户停止 DSH 后，待重启提示可以变为“下次启动生效”。
- 观察到 DSH 从停止状态重新进入新的运行状态后，清除待重启标记并刷新已安装列表。
- 不自动终止正在执行的会话，不自动刷新 DSH iframe。

## 9. 错误处理

| 场景 | 页面行为 |
| --- | --- |
| DSH 运行时缺失 | 保持市场可进入，禁用搜索和管理，提供首页引导 |
| pnpm 准备失败 | 保持只读，展示私有工具安装错误 |
| registry 不可达 | 保留已有结果，显示网络错误并允许重试 |
| 搜索 JSON 无效 | 返回协议错误，不把原始响应当作 HTML 渲染 |
| 清单不符合市场协议 | 从可安装结果中排除；开发日志记录简短原因 |
| 安装或卸载非零退出 | 展示退出码和截断日志，不修改前端安装状态 |
| 操作后状态复核失败 | 返回失败，并提示检查 profile 与 DSH 日志 |
| 已有写操作 | 禁用重复提交并提示等待当前操作完成 |

错误信息应优先告诉用户下一步如何处理，技术日志放在可展开区域，不在页面主状态中堆叠完整命令输出。

## 10. 测试方案

### 10.1 Rust 单元测试

- 解析合法、空数组、字段缺失和畸形的 pnpm 搜索 JSON。
- 精确接受 `@p-dsh-market/example`，拒绝相似 scope、无 scope、路径穿越、空名称和命令参数注入。
- 校验 `main`、client export、web platform、bundle patch 和 `dsh.market` capabilities。
- 合并搜索结果与已安装版本，处理重复包名和版本缺失。
- 托管/本地两种 DSH 命令参数构造保持一致。
- 路径包含空格时仍以独立 argv 传递。
- 写操作互斥在成功、失败和 panic-safe 清理路径上均可释放。
- 日志截断和敏感字段脱敏。

### 10.2 隔离集成测试

- 使用临时 `DSH_HOME`，不得读写用户真实的 `~/.dsh`。
- 使用伪造 DSH/pnpm 可执行文件返回固定 JSON 和退出码。
- 验证搜索、安装、卸载、非零退出、超时和 pnpm 准备失败。
- 验证安装命令固定版本、卸载命令不携带额外参数。
- 自动测试不得执行 `npm publish`、真实安装市场包或读取 npm 凭据。

### 10.3 前端与契约测试

- HTML 存在 Logo 旁市场入口和独立市场视图。
- JavaScript 包含 `home / dsh / market` 三态切换。
- 市场按钮不会触发窗口拖动。
- DSH 未运行时市场仍能打开且处于只读状态。
- 搜索中、空结果、失败、已安装、待重启状态正确渲染。
- 亮色、暗色和窄窗口下布局可用。
- 新增 JavaScript 通过 `node --check`。

### 10.4 手工验收

1. 未准备 DSH 时进入市场，确认只读引导正确。
2. 首次进入时准备桌面私有 pnpm，确认没有修改系统 PATH。
3. 搜索市场，确认只出现通过清单校验的 `@p-dsh-market/*` 包。
4. 安装插件，确认 profile 依赖和 bundle 列表由 DSH CLI 更新。
5. DSH 运行中安装，确认不会热加载，并显示重启提示。
6. 重启后确认 Skill、宿主逻辑和 Web UI 同时生效。
